# Knowledges

「前にどうしてた」「メモにあった」「設定の意図を思い出したい」など、答えが本人の過去に依存する場合は回答前に検索する。技術名や案件名が出ただけで一律に検索しない。現在値や最新情報だけを問う依頼には使わず、過去に決めた値を問うなら使う。`/knowledges` や「メモ検索して」も対象。

## 検索先と手段

- 個人の学習、dotfiles、キャリア・転職は home（`mcp__home-memo__search_knowledge`）。業務案件や社内固有の判断は work（`mcp__work-memo__search_knowledge`）。境界が曖昧なら両方を調べる。`~/.is_work_pc` は優先順位の補助にとどめ、話題を優先する。
- 概念、言い換え、日英をまたぐ探し物は MCP の意味検索から始める。識別子、パス、エラー文字列の完全一致や網羅性が必要なら、ローカルノートが使える環境で `kb search` を使う。例: `kb search "<語>" -F -n work -l`。
- 質問の核となる短い検索語で少数の候補を確認する。結果が薄いときだけ表記や言語を変え、別の手段や原典の読み取りで補う。既に同じ話題の十分な検索結果が会話にあるなら再検索は不要だが、新しい切り口や現在性の確認には検索する。

## 回答

ヒットした内容を要約し、home/work と `knowledge/xxx.md` の原典を示す。日付が分かる古いノートは現在の事実と区別し、必要なら現状を別途確認する。ノートと一般知識が食い違う場合は差を明示する。見つからない、または検索手段が使えない場合はその旨を伝え、確認できていない個人の過去を推測で埋めない。ノートの作成・更新は明示された依頼がある場合だけ行う。
